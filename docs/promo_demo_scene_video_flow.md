# 宣传片演示 · 场景视频生成流程（需求描述）

> 类型：**一次性宣传片录制脚手架，非上线功能**
> 目的：录制 Pawlight 使用流程宣传片时，稳定演示"付费解锁 → 输入场景 → 星球观察窗生成动态画像"这段体验
> 日期：2026-09-10
> 关联：[11 AI 场景画像 API 调研](11_ai_scene_portrait_api_research.md)（真实功能设计，本文件不涉及）

---

## 1. 背景

真实的场景画像功能要接图像 / 视频生成 API，结果不可控、耗时不稳定，不适合录屏。本脚手架用**预置素材 + 固定倒计时**完整模拟这套体验，让宣传片能一镜到底、可复现地录制。

- 所有"生成结果"由用户预先提供的素材驱动：候选画像 ×N、最终视频 ×1
- 所有"生成耗时"用固定倒计时模拟：出图 45 秒、出视频 85 秒
- 逻辑全部关在开关后面，不进正式包；录完可整段移除

---

## 2. 触发条件

同时满足：

1. 用户已上传宠物主照片（`currentPet.mainPhoto` 存在）
2. 在**任意购买入口**（选档页 `TierSelectView` / 权益页 `EntitlementView`）完成支付并拿到 `.success`

→ 支付成功后，用户下次落到**首页 Tab** 时，自动弹出「场景描述输入」（S1）。

> 说明：解耦于具体购买页和其后的成功页导航，统一在"回到首页"这个时机触发，保证从两个入口进都一致。

---

## 3. 流程状态机

| 状态 | 进入条件 | 界面表现 | 退出条件 |
| --- | --- | --- | --- |
| **S0 空闲** | 初始 | 观察窗正常显示宠物主照片 | 支付成功 + 有照片 + 回到首页 |
| **S1 场景输入** | 从 S0 | 弹出输入卡片：标题 +多行文本框 + 「生成」按钮 | 用户点「生成」 |
| **S2 生成图片中** | 从 S1 | 关闭输入卡片；观察窗进入 loading 态，文案「正在为 TA 生成画像…」 | 后台计时 **45s** 到 |
| **S3 选择画像** | 从 S2 | 弹出候选画像卡片：展示用户提供的 N 张，点任意一张即确认 | 用户点选一张 |
| **S4 制作视频中** | 从 S3 | 关闭候选卡片；观察窗 loading 态文案更新为「正在让 TA 动起来…」 | 后台计时 **85s** 到 |
| **S5 完成** | 从 S4 | 观察窗替换为循环播放的视频（用户提供）：静音、自动循环、进页即播 | 持久保持（除非「重置演示」） |

---

## 4. 各状态细节要求

### S1 · 场景输入
- 居中模态卡片，复用 App 现有柔和弹窗风格（非系统 `alert`）
- 内容：标题（如「想看到 TA 在什么样的地方？」）+ 多行文本框 + 占位文案 + 「生成」主按钮
- 文本框留空也能提交（演示容错）
- 提交后卡片关闭，停留在首页

### S2 / S4 · 生成中
- 观察窗中心区域渲染为 loading 态：**复用现有呼吸光晕 / 柔和微动视觉**，不用系统转圈
- 文案位于观察窗下方或中心：S2「正在为 TA 生成画像…」、S4「正在让 TA 动起来…」（最终文案待定）
- **不显示倒计时数字**（避免观众看出是模拟）
- 倒计时基于时间戳；期间可自由切 Tab / 返回，回首页时按已流逝时间续算
- loading 态会被完整录进画面（可能连续 45s / 85s），视觉上要耐看、不呆板

### S3 · 选择画像
- 弹出卡片 / 半屏 sheet
- 展示用户提供的 N 张候选（设计上支持 2~6 张），等比缩略，圆角矩形或圆形
- **点击任意一张即确认**，无二次弹窗
- 无「重新生成」「都不满意」入口（演示不需要）

### S5 · 视频
- 占满观察窗中心圆形区域，`aspectFill` 裁切，圆形蒙版
- 静音 + 循环 + 自动播放，进首页即播
- 观察窗外围的光晕 / 星点 / 新月等装饰保持不变

---

## 5. 持久化与可重复录制

- S5 完成后写入本地标记（含选中的视频标识）；App 重启后观察窗仍显示该视频，方便补拍其他镜头
- 倒计时中途被杀进程：重启后按时间戳判断——已超时则直接进入下一交互态，未超时则续算
- 提供「重置宣传片演示」入口（Debug 菜单）：一键回到 S0、清除所有标记，便于多次重录

---

## 6. 素材需求（用户提供）

| 素材 | 规格建议 | 用途 |
| --- | --- | --- |
| 宠物主照片 | 沿用现有 Mock 照片，或另提供 1 张 | 观察窗初始展示（即"已上传"的那张） |
| 候选画像 | N 张（建议 3~4），统一比例（建议 1:1），短边 ≥ 1024，PNG / JPG | S3 展示、S2 结束后弹出 |
| 最终视频 | MP4（H.264 或 HEVC），静音，建议 3~6s 且首尾可无缝循环，短边 ≥ 720 | S5 播放；比例建议 1:1（圆形窗），或给 16:9 由开发裁切 |

交付：放入约定目录（开发建目录并给命名规范），或直接发文件。

---

## 7. 明确不做

- 不接任何图像 / 视频生成 API
- 不做真实的场景解析、身份提取、多次重生成、局部编辑
- 不改购买核心逻辑、`entitlement` 解锁逻辑、Product ID
- 不做 H5 侧任何改动
- 不做弱网 / 失败 / 超时态
- 倒计时数值（45s / 85s）硬编码，不做线上可配
- 不做多宠物、不做历史记录、不做"再做一个"

---

## 8. 验收标准

- 从「支付成功」到「观察窗播放视频」可一镜到底录制，中途无需开发者干预
- 时序稳定可复现：每次都是 输入 → 45s → 选图 → 85s → 视频
- loading 态、弹窗的视觉与 App 现有风格一致，不穿帮
- 「重置演示」能让整个流程从头再来
- 关闭开关后，App 行为与现在完全一致
