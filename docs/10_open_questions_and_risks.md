# 10 Open Questions And Risks

本文件记录进入真实开发前仍需确认的问题、风险，以及HTML原型与PRD可能存在的实现口径差异。以下事项不建议由开发单方面决定。

## 1. 待确认问题

| 问题 | 当前建议 / 原型口径 | 风险 | 需要谁确认 |
| --- | --- | --- | --- |
| 主照片是否计入照片额度 | 建议不计入相册9/50额度，但计入图片资产管理 | 用户理解和存储成本口径不一致 | 产品、技术、财务 |
| 付费“更长期保存感”的具体表达 | 不承诺永久，使用更安心/更长期 | 法务承诺风险 | 产品、法务 |
| H5分享链接是否长期有效 | V1暂不做有效期和多链接管理 | 链接被转发后的隐私风险 | 产品、安全 |
| 访客抱抱去重方式 | 本地匿名ID + 服务端轻去重 | 过严会误伤，过松会刷抱抱 | 技术、产品 |
| 是否需要删除照片 | PRD P1可选 | 不支持删除会影响用户控制感 | 产品 |
| 是否需要删除宠物 | PRD未明确V1主能力 | 删除后数据和H5状态复杂 | 产品、法务 |
| 注销账号后的数据处理 | 需删除或不可访问 | 隐私与情感资产冲突 | 法务、产品、技术 |
| H5页面SEO/隐私边界 | 不进入公开列表，不做SEO导流 | 搜索引擎收录隐私内容 | 产品、安全 |
| iOS支付路径 | 可能需要App Store IAP | 平台规则和审核风险 | 产品、法务、客户端 |
| 中国大陆支付与App Store规则 | 待确认 | 价格、商品类型、合规风险 | 产品、法务 |
| 图片存储成本 | 免费9、付费50，需压缩缩略图 | 成本随分享访问增长 | 技术、财务 |
| 未成年人/敏感纪念内容风控 | V1无公开社区，但H5可传播 | 内容合规风险 | 产品、法务 |
| 未来多宠扩展 | 数据保留pet_id，UI暂不开放 | 权益策略会影响表设计 | 产品 |
| 未来周年提醒和Push扩展 | V1保存日期，不做提醒 | 过早索权影响体验 | 产品、客户端 |

## 2. HTML原型与真实开发的差异

| 原型表现 | 真实开发注意 |
| --- | --- |
| 右侧开发走查面板存在 | 正式产品不包含 |
| `state.photos`、`state.hugs`、`state.letters`为内存数组 | 后端需落库并分页/排序 |
| H5开发导航可返回App路由 | 正式H5应打开App、下载App或进入创建引导 |
| “内测体验”tag | 可替换，不一定是正式产品文案 |
| 支付弹窗中的开发测试状态 | 正式App应接入App Store支付确认 |
| 上传页中的开发测试状态 | 正式App只展示真实上传流程 |
| 主图占位为CSS模拟 | 正式产品必须加载真实图片 |
| 抱抱去重为前端状态 | 正式必须服务端去重 |

## 3. 产品边界风险

V1开发中需持续避免范围蔓延：

- 不增加社区、发现页、公共地图；
- 不增加评论、留言、访客上传；
- 不增加消息中心和Push；
- 不增加AI聊天、宠物回复、宠物复活；
- 不增加任务、积分、排行榜；
- 不增加商城和强促销；
- 不增加视频上传；
- 不实现复杂多宠管理。

## 4. 情绪表达风险

风险：

- 过度殡葬化；
- 过度治疗化；
- 暗示宠物会回应；
- 抱抱变成点赞或热度；
- 付费墙阻断他人心意。

应对：

- 文案保持“回来看看、慢慢留下、轻轻抱抱”；
- 不使用复活、召回、回复、治疗、排行、热度；
- 抱抱记录免费/付费均完整可见；
- 权益增强照片和信箱，不阻断核心闭环。

## 5. 技术风险

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 图片成本 | H5访问和照片数量带来存储/CDN成本 | 压缩、缩略图、数量限制 |
| 并发额度 | 多端同时上传可能绕过前端额度 | 后端上传前和完成时双重校验 |
| H5隐私 | 链接转发不可控 | 清晰权限说明，可改回私密 |
| 购买恢复 | iOS交易校验复杂 | 服务端校验平台交易 |
| 删除/注销 | 数据删除与纪念保存冲突 | 法务确认后实现 |
| 时间日期 | 日期精度多样 | 使用date_partial结构 |
