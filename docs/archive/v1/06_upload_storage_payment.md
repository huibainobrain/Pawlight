# 06 Upload Storage Payment

## 1. 图片上传

### 1.1 主照片上传

主照片是创建宠物的必填项，也是首页、回忆页、H5页、分享预览的视觉锚点。

建议流程：

1. App选择图片；
2. 客户端基础校验格式；
3. 客户端压缩/裁剪预处理；
4. 请求上传凭证；
5. 上传到对象存储；
6. 服务端确认并生成 `photo_id`；
7. 创建宠物或替换主图时绑定 `main_photo_id`。

### 1.2 相册照片上传

相册照片是创建后的渐进补充项，不阻断宠物创建。

建议流程：

1. 前端查询额度；
2. 未满额时选择图片；
3. 获取上传凭证；
4. 上传并确认；
5. 服务端写入 Photo；
6. 前端刷新相册列表和容量提示。

### 1.3 支持格式

V1建议支持：

- JPEG；
- PNG；
- HEIC/HEIF，iOS端转码或服务端兼容；
- WebP可作为展示格式，不一定作为上传格式。

### 1.4 不支持视频

V1不支持视频上传，免费档和付费档均不支持。

推荐提示：

```text
V1暂时只支持图片上传，视频回忆会在后续版本考虑。
```

### 1.5 图片压缩

建议：

- 客户端上传前压缩长边，如 2048px 或 2560px；
- 服务端生成缩略图；
- H5优先加载缩略图或中等清晰版本；
- 原始或高清版本是否保留需结合成本确认。

### 1.6 尺寸限制

建议初始限制：

- 单图原始文件不超过 10MB 或团队成本可接受值；
- 压缩后目标 500KB-2MB 量级，视画质调整；
- 拒绝异常图片、损坏文件、非图片格式。

### 1.7 上传失败

前端表现：

- 主照片：阻止进入下一步，提示重新试一次；
- 相册照片：保留当前页面，允许重新上传；
- 视频：提示暂不支持。

后端错误：

- `UNSUPPORTED_FILE_TYPE`
- `PHOTO_UPLOAD_FAILED`
- `PHOTO_LIMIT_REACHED`
- `FILE_TOO_LARGE`
- `IMAGE_PROCESSING_FAILED`

### 1.8 存储路径建议

```text
/users/{user_id}/pets/{pet_id}/main/{photo_id}.jpg
/users/{user_id}/pets/{pet_id}/album/{photo_id}.jpg
/users/{user_id}/pets/{pet_id}/thumbs/{photo_id}.jpg
```

不要把文件路径设计成只依赖 user_id；所有宠物内容必须保留 `pet_id`，为未来多宠预留。

### 1.9 图片删除策略

待确认是否V1提供删除照片。若提供：

- 相册照片可软删除；
- 主照片不可直接删除，只能替换；
- 删除后H5不再展示；
- CDN缓存需考虑延迟失效；
- 账号注销时需按隐私政策处理图片。

### 1.10 未来视频预留

V1不做视频，但数据结构可预留：

- `photo.type` 或未来 `media.type`；
- `duration`；
- `transcode_status`；
- `cover_url`；
- `video_url`。

不要在V1用户界面承诺视频上线时间。

## 2. 额度规则

### 2.1 基础规则

| 权益 | 相册照片上限 | 天堂信箱 |
| --- | --- | --- |
| 免费档 | 9张 | 锁定 |
| 付费档 | 50张 | 可用 |

### 2.2 主照片是否计入额度

建议：主照片不计入相册额度。

理由：

- PRD建议用户侧表达为“相册最多可保存X张照片”，主照片作为入驻必填主图单独处理；
- 这样用户理解更简单；
- HTML原型当前也将主照片和 `state.photos` 相册数组分开。

待确认点：后端成本测算时仍应将主照片纳入总图片资产管理。

### 2.3 达到额度后的前端表现

免费档达到9张后：

- 添加按钮可保留；
- 点击后展示上限提示；
- 引导了解完整纪念空间；
- 不使用强促销、倒计时、会员压迫式文案。

付费档达到50张后：

- 提示已达当前上限；
- 不展示升级促销；
- 可引导未来整理或删除照片，若V1支持删除。

### 2.4 后端额度校验

后端在以下位置必须校验：

- 获取上传凭证前；
- 上传完成确认时；
- 批量上传时；
- 权益变更后；
- 并发上传时。

建议校验逻辑：

```text
photo_count = count(active album photos by pet_id)
limit = entitlement.photo_limit by user_id
if photo_count >= limit:
  reject PHOTO_LIMIT_REACHED
```

## 3. 支付

### 3.1 付费模式

V1付费档为一次性买断：

- 促销价：¥29.9；
- 展示原价：¥59.9；
- 一次性开启完整纪念空间；
- 第三档仅展示未来开放，不可购买。

### 3.2 购买成功

购买成功后：

- 权益状态更新为 paid；
- 照片额度变为50；
- 天堂信箱开放；
- 权益页展示已开通态；
- 首页不再展示强升级广告；
- H5分享和抱抱记录继续完整可用。

### 3.3 购买失败 / 取消

购买失败或取消后：

- 不清空宠物名字；
- 不清空宠物类型；
- 不清空主照片；
- 允许重新支付；
- 允许选择免费档创建；
- 允许返回权益选择页。

### 3.4 恢复购买

iOS场景必须提供恢复购买入口。

恢复成功：

- 同步 paid 权益；
- 刷新权益页和信箱状态；
- 恢复照片额度。

恢复失败：

```text
暂时没有找到可恢复的购买记录
```

### 3.5 权益绑定账号

权益绑定 `user_id`，不绑定 `pet_id`。V1虽然只支持一只宠物，但未来多宠策略不能被当前表结构锁死。

### 3.6 App Store / 中国大陆支付待确认

真实开发前需要确认：

- 是否必须走 App Store IAP；
- 中国大陆场景是否存在额外支付限制；
- 商品类型使用非消耗型还是其他类型；
- 价格展示、促销价和原价是否符合平台规则；
- 退款后权益如何处理。
